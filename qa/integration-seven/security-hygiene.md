## Dependencies and audit

The seven completed branches changed no package metadata. Integration adds exact development dependency `playwright@1.61.1` because tracked browser acceptance tools import it; runtime dependencies remain otherwise unchanged. The lockfile was regenerated by npm rather than hand-edited. Installed top-level versions are Electron `33.4.11`, Playwright `1.61.1`, and Three.js `0.185.1`.

`npm audit --json` reports one high-severity direct-development vulnerability group for Electron `<=39.8.4`. The available automatic remediation is Electron `43.1.1`, a semver-major upgrade. Electron `^33.2.0` is inherited from original main; the integration did not introduce or widen it. A major Electron upgrade is deliberately not folded into this multi-system integration without its own compatibility/security validation. This is a known release-security limitation, not a clean-audit claim.

## Electron isolation

The application uses its existing local Electron entry point; final clean-worktree launch is a required release gate. No API key, remote service credential, browser profile, external database, or development-only global is exposed by the integrated systems. The browser QA APIs are explicit local debug/acceptance surfaces already used by repository tests; production gameplay does not depend on them for state ownership.
